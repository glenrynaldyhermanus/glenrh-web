HRIS

Talent acquisition automation: write the hiring rules once, and every candidate gets measured the same way.

17

The setting

Too many CVs, not enough clarity.

Hiring for IT roles usually lives in spreadsheets and chat threads. Nobody agrees on what a “middle backend engineer” should know, so every CV gets judged differently.

I wanted one place where the rules are written down once, and a workflow that does the first round of screening without anyone copying and pasting.

Role
Design, frontend, backend, automation
When
August 2026
Platform
Web dashboard and n8n
Status
Live, behind a login
The quest

Write the rules once. Let the workflow run.

A skill matrix sets the required skills for every role and level. When a manager opens a manpower request, those skills fill themselves in.

Then an n8n workflow takes over. It reads each candidate against the request and sends back a match score, the skills they bring, the skills that are missing, a short summary and a recommendation.

The craft

The app holds the rules. n8n does the work.

A single Next.js app with typed API routes. Prisma talks to PostgreSQL, sessions are signed JWTs, and every request sends a clean payload to n8n, so the matching logic can change without a deploy.

The ending

HRIS is live at hris.glenrh.com. It holds real candidate data, so only the skill matrix is shown here, on purpose.
